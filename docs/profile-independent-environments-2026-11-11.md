# Profile 独立环境修复（2026-11-11）

原实现虽然将文件分目录保存，但新建账号时复制了当前设备身份，导致两个 profile 的 UUID、MAC、IDFA 和设备参数相同。本次按每个账号一份固定设备环境修正。

- 新建 profile 时生成独立 UUID、MAC、iOS IDFA、安装时间和设备参数，立即写入该 profile 的 identity.json。Android 使用独立 UUID/MAC，IMEI 保持原协议的空值。
- 城市和定位初始值沿用当前配置，之后各 profile 独立保存、单独修改。账号密码、登录会话、学校选择和点位仍相互隔离。
- 切换或重启只加载保存的身份，不重新随机。设备页手动“随机生成”也改为完整生成，包括此前遗漏的 MAC。
- 启动时检查旧 profile 中重复的设备 ID，始终优先保留原有账号（与列表顺序无关）。修复其他重复账号前，在该账号的 environment-backups/<UUID>/ 中完整备份旧身份与会话，目录 0700、文件 0600。
- 旧会话与原设备身份绑定，修复时先清除该账号的本地会话，再原子写入独立身份，提示重新登录。密码、配置、记录和原有账号不变；不向服务端请求登出。
- 备份失败时不修改身份或会话；身份写入失败时恢复旧会话。进程中断也不会将新身份与旧设备的 token 一起使用。已修复账号不会重复生成环境。
- Android 自动读取本机信息仅作用于原有账号；启动读取结果若在切换后才返回，会被忽略。其他 profile 使用其保存的设备参数。设备页输入控件按 profile 区分。
- 公开的学校路网继续按学校、范围与版本共享缓存，账号会话和私有状态保存在各自目录。

验证：GUI workspace 374 passed、2 ignored；CLI workspace 292 passed、2 ignored；默认/CLI 全目标及 Android ARM64 Clippy 使用 -D warnings 通过。新增测试覆盖两个平台的环境唯一性和重启稳定性、旧重复环境的一次性备份/修复、备份失败不修改数据；原有后台线程隔离、手机交互与其他回归继续通过。

更新后的三平台产物仍位于 dist。首次打开新版时会修复旧的重复 profile；原有账号继续使用现有身份与登录态，被修复的其他账号需要重新登录。
